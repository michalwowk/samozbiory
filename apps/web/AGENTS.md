# apps/web

The application: farm directory, map, buyer and farmer panels, and the location pages that carry search
traffic. Repo-wide rules live in the root [`AGENTS.md`](../../AGENTS.md).

## Data access

**Never import `@repo/database` here.** ESLint fails the build on it. All reads and writes go through
`@repo/api`, which owns Zod input validation and authorisation
([ADR 0012](../../docs/decisions/0012-data-access-boundary.md)).

Server Components call `@repo/api` functions directly — in-process, typed, no HTTP. That is the default
and the cheapest path; reach for a network transport only when the browser itself must initiate the
request (map panning, filters without reload).

## Location pages are the product

A page under `/samozbiory/...` exists to be indexed, so:

- Its canonical content is a **server-rendered list** of farms plus `JSON-LD`. The map is a client
  component Google cannot execute — an enhancement, never the content.
- `generateStaticParams` reads `Region` from the database and emits only params that clear the density
  threshold. Pages below the threshold must not render empty; they 404
  ([ADR 0006](../../docs/decisions/0006-geo-seo-density-gated-pages.md)).
- URL shapes are fixed and must not be changed casually. Migrating indexed URLs is the most expensive
  mistake available in this project.

## Next 16 conventions that differ from what you remember

| Do this | Not this | Why |
|---|---|---|
| `proxy.ts` | `middleware.ts` | Next 16 renamed the file convention. Same functionality; the old name still works but warns on every build. See `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md` |
| `import { locale } from "next/root-params"` | `requestLocale` from next-intl | next-intl 4.14 deprecates `requestLocale` in favour of Next 16 root params. Docs: `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/next-root-params.md` |
| `next.config.ts` | `next.config.js` | Config is TypeScript here, and it is wrapped by `createNextIntlPlugin` |
| `sitemap(props: { id: Promise<string> })`, awaited | `{ id }: { id: number }` | Next 16 passes the id as a **promise resolving to a string**. Treating it as a number gives `NaN` bounds, and `slice(NaN, NaN)` returns `[]` — a silently empty sitemap behind a green build |
| `metadataBase` in the root layout | relying on relative `alternates.canonical` | Without it, canonicals render relative and Next warns |

### The proxy matcher

`proxy.ts` uses `matcher: ["/((?!_next|_vercel).*)"]` and excludes everything else **in code**, which
looks redundant and is not.

The documented negative-lookahead shape — `/((?!api|sitemap|robots|.*\..*).*)` — silently failed to
match nested paths in this project. `/` was rewritten, `/samozbiory/malopolskie` was not, so every
location page 404ed while the build printed all 16 of them as prerendered. Diagnosing it took reading
`x-middleware-rewrite` on the response.

If you tighten that matcher, verify with a **nested** path, not just `/`.

### generateSitemaps has no index

`generateSitemaps()` serves `/sitemap/<id>.xml` and Next creates **no** `/sitemap.xml`. `robots.ts`
therefore lists each chunk, derived from the same function that produces them. Pointing robots.txt at a
single `/sitemap.xml` sends crawlers to a 404.

`next/root-params` types are generated by `next dev` / `next build` / `next typegen`, so a fresh clone must
build once before those imports typecheck.

## Copy

Polish product copy lives in `messages/pl.json`, never as a string literal in a component. Polish is
the unprefixed default locale (`localePrefix: 'as-needed'`), so `/samozbiory/malopolskie` has no
`/pl/` segment and must not gain one ([ADR 0011](../../docs/decisions/0011-i18n-with-next-intl.md)).

`next.config.ts` carries a permanent redirect from `/pl/:path+` and `/pl` to the unprefixed equivalents.
Without it both URLs answer 200 and every location page exists twice — duplicate content on a product
whose distribution is search. next-intl has no option for this. **Do not remove those redirects**, and
note the `:path+` rather than `:path*`: with `*` the bare `/pl` matches the first rule and produces an
empty destination, i.e. a 308 with no `Location` header.

Read `searchParams` through **nuqs** (`NuqsAdapter` is already wired in the locale layout), and validate
them with Zod — filters and the map bbox are the main untrusted input surface here
([ADR 0007](../../docs/decisions/0007-prisma-owns-types-zod-guards-inputs.md)).

## Tests

```sh
pnpm --filter web test:e2e      # requires a seeded database; builds first
```

The suite runs against a **production build**, because what it tests is `generateStaticParams` and the
density gate, which only behave realistically once pages are prerendered.

`e2e/location-pages.spec.ts` is the mandatory suite. Every other defect here announces itself; the
density gate does not — if it breaks, thousands of empty pages get generated, nothing errors, and the
penalty arrives months later. Both it and the unit tests in `@repo/api` were counter-tested by lowering
the threshold: two e2e tests and one unit test fail. Do not weaken them.

`data-farm-slug` on each list item is load-bearing — the tests assert against it to prove the list is in
the server response rather than hydrated in.

## Forms

TanStack Form, not React Hook Form. **Do not run `shadcn add form`** — that component is an RHF wrapper
and adding it drags React Hook Form back into the tree. Use the `<Field>` wrapper from `@repo/ui`
([ADR 0009](../../docs/decisions/0009-tanstack-form-over-react-hook-form.md)).

Components come from `@repo/ui`. Run `shadcn add` only from `packages/ui`, never from here
([ADR 0008](../../docs/decisions/0008-design-tokens-as-typescript.md)).
